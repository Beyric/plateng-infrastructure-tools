## Why

- **Sonar:** Community Edition has one branch per project, so branch, PR and `main` analyses share one issue history.
  `dec09c4` (main) and `ad53759` (#53 PR head) have the **same tree** (`395c3a2`), yet the PR passed and main failed:
  two branch analyses in between closed 3 issues that `main`'s next analysis reopened as "new".
- **Superadmin:** since #49 admins set their own password from a single-use link; the very first one has no admin to
  invite it.
- **`SECRET_KEY` order:** the setup token is keyed with `SECRET_KEY` (`app/core/security.py:70,83`). Rotating *after*
  issuing the link would void it and the new session, so rotation went first. It is safe to rotate: it signs JWTs and
  setup/reset tokens only; nothing is encrypted with it; ID fingerprints use `KYC_FINGERPRINT_KEY` (never rotated).

## How (procedure as run)

1. Rotate (Adebayo; generated by Vault, not the laptop):
   `kubectl exec -n vault vault-0 -- sh -c 'K=$(vault write -field=random_bytes sys/tools/random/64 format=hex) && printf "{\"SECRET_KEY\":\"%s\"}" "$K" | vault kv patch secret/weysure/prod - >/dev/null && echo "SECRET_KEY: $(vault kv get -field=SECRET_KEY secret/weysure/prod | tr -d "\n" | wc -c) chars"'`
   then force-sync `weysure-app-config`. Every user and admin session ends once.
2. Insert the row, idempotent (`INSERT … SELECT … WHERE NOT EXISTS (SELECT 1 FROM admins)`), app-format id
   `'WS' || extract(epoch FROM now())::bigint || '-' || left(gen_random_uuid()::text, 8)`, placeholder hash `'!'`.
3. **Immediately** issue the link from an api pod, in a terminal nobody else can read:
   `kubectl -n weysure-prod exec -it <api-pod> -c api -- bash -c 'set -a; . "$VAULT_ENV_FILE"; set +a; exec python scripts/admin_setup_link.py "$1" <operator>' _ "$E"`
4. Open the link, set the password, sign in; invite a second superadmin from the console.

Decisions: Sonar **option 1 now + option 2** (PR analyses into `weysure-api-pr` / `weysure-web-pr`) chosen; option 3
(Developer Edition / community branch plugin) rejected under the scope freeze. The operator is also the recipient, so
the link never left Adebayo's terminal.

## Gotchas hit (read before repeating)

| Trap | What happened | Rule |
|---|---|---|
| `exec` lacks the entrypoint's env | `DATABASE_URL` is **not** in the container env; `boot/docker-run.sh` sources it from `$VAULT_ENV_FILE` (`/vault/secrets/env`). The script's own `docker exec` usage line is Compose-era | Source `$VAULT_ENV_FILE` first (step 3) |
| Script not in the image | the Dockerfile copies named scripts only | check the image (`ls /app/scripts`), not the repo |
| Pasted placeholders | step 1 first ran with the example email/names | prompt with `read -r`, refuse empty/placeholder input, keep the value in one variable for both steps |
| Shell rewrote SQL | `'$2%'` inside double quotes became `'%'` (always true); the same query also contained `'!'` and returned a wrong `placeholder_emails=1` | single-quote SQL that needs no shell variables; `chr(33)` for `!`, `\$` for `$` |
| A wrong check → a "fix" | the follow-up `UPDATE` matched 0 rows (the row was already right) | on a contradiction, read the raw row before writing again; keep `WHERE` narrow; rowcount 0 = stop |
| Wrong column guess | `reference` (KYC query) is `provider_reference` | check every column at the **deployed** tag |

## Operate / roll back

- Lost the only superadmin password: run step 3 again for that email (voids the old password and sessions, writes an
  audit row). Never as a Job: the script refuses a non-TTY stdout because the link is a credential.
- `SECRET_KEY` rollback: `vault kv rollback -version=<n> secret/weysure/prod` + force-sync (KV v2 keeps versions).
  Rarely wanted: the reason to rotate was exposure.
