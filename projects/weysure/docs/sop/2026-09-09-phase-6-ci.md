## Findings

**㉕ — `terraform-aws-modules/eks` ignores `desired_size` after creation.** The module sets
`ignore_changes` on it so the cluster autoscaler owns it. Growing the system node group from
one node to two required `min_size = 2`, and the live group needed one
`aws eks update-nodegroup-config` because the module will not push `desired_size` at all.
Rule: size managed node groups with `min_size`; `desired_size` is a creation-time hint.

**㉖ — A plugin-list change *does* roll the Jenkins pod; do not delete it by hand.**
An earlier session concluded the opposite. Evidence from 2026-09-09: Argo synced gitops #13
at 13:52:12Z, the StatefulSet generation went 3→4 (`checksum/config` on the pod template
changed), and `jenkins-0` was recreated at 13:52:16Z — killing API build #5. The manual
delete five minutes earlier had restarted it once already, for nothing. What does *not*
restart Jenkins is a JCasC change (the sidecar reloads it). Rule: merge, watch
`argocd app get jenkins` reach `Synced`, let the rollout happen, then trigger builds.

**㉗ — The GitHub App needed two permissions the branch-source plugin does not ask for
until it fails.** `Pull requests: read` to discover PR heads and `Commit statuses: write`
to report back; both were added and *accepted on the installation* afterwards. The org
folder also does not scan on creation — the first scan was a `POST …/build` with a CSRF
crumb. Both are now in the Jenkins runbook.

**㉘ — Kaniko cached layers do not carry deletions.** The runtime stage's `RUN rm -rf
/usr/local/lib/node_modules …` produced a correct image once. The *branch* build of the same
PR pushed that layer to ECR as cache (`weysure-web:ede7d01e…`, 15:52), and the `main` build
restored it — without the whiteouts — so npm and its `tar` were back. Kaniko keys the cache
on command text + parent layers and stores the diff as a tarball; whiteout handling on
restore is unreliable. Rule: **add to a clean base, never subtract from a dirty one.** Also
noted: branch builds push cache tags into the production ECR repo; a lifecycle policy for
untagged/cache images is in the deferred table.

**㉙ — Pinning a Debian codename is a time bomb.** `python:3.11-slim-bullseye` built for
years and then could not run `apt-get update`: Debian 11 LTS ended and the
`bullseye-security` Release file expired. Pin the *language* version, track *current*
Debian (`slim-bookworm`), and let Trivy say when the base has aged.

**㉚ — Every official `node` image ships a vulnerable `tar` through npm.** `node:20`, `22`
and `24` on Alpine all carry CVE-2026-59873 in npm's bundled `tar`; distroless `nodejs22`
carries an unfixed-in-image `libssl3` CRITICAL instead. The runtime is therefore
`alpine:3.22` + `libstdc++` + `libgcc` + the `node` binary copied from the build stage
(same Alpine minor, so the ABI matches). No npm, no shell tooling beyond BusyBox, 68 MB.
Node 20 also reached end-of-life in April 2026; build stages moved to `node:22-alpine3.22`.

**Sonar token stored empty, and an unasserted edit.** The first `sonar-token` write to Vault
stored a zero-length value (verify by *length*, ADR rule from Phase 3), and the JCasC edit
adding the credential was a `str.replace` that matched nothing and reported success. Both
now assert: `vault kv get -field | wc -c`, and Python edits `assert old in s`.

**Local reproduction on macOS.** `timeout` is absent (`perl -e 'alarm N; exec @ARGV'`),
`PIPESTATUS` is bash (`$pipestatus` in zsh), pydantic-settings reads a developer's `.env`
so tests must run from a `git archive` copy, and a resource-starved Docker Desktop stalls
silently under `npm ci`. All recorded in `docs/conventions/TOOLCHAIN.md`.

## Rollback

Pipelines are code in the app repos — revert the Jenkinsfile PR. A bad promote is a one-line
revert on gitops `main` (and until Phase 7, promotes deploy nothing). Jenkins and SonarQube
are Argo applications; deleting `bootstrap/apps/jenkins.yaml` removes the controller and
its PVC — the config is JCasC, so re-adding it restores everything except build history.
