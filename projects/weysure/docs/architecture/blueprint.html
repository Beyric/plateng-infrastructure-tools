Fourteen findings from a read-only investigation of the AWS account, both application repositories, and the uncommitted Terraform. Every claim is cited to a file and line, so any of them can be re-derived.

The finding that shrank the project

Supabase looked like a platform dependency. Tracing every reference showed it is only hosted Postgres: passwords live in the application's own users table, hashed by passlib, with JWTs signed by the application's own key. app/core/supabase.py is never imported.

That matters more than it sounds. Had passwords lived in Supabase's managed auth schema, they could not be exported — the only exits would have been a forced password reset for every user of a wallet application, or a months-long migration shim. The migration is data-only.

Accepted risk · single NAT Gateway

Both private subnets route through one NAT Gateway in us-east-1a. An AZ-a failure removes egress for healthy AZ-b nodes too — image pulls and outbound API calls stop. It saves $33/month. Revisit on a budget increase or the first AZ incident.

Compute & cost

The originally configured two t3.medium nodes provide ~3.5 vCPU / 6.4 GiB allocatable. The platform stack requests 4.5–6 vCPU and 13–17 GiB. Pods would sit Pending — the problem was arithmetic, not configuration.

Why m6i, not t3

t3 is burstable: it earns CPU credits while idle and sustains only 20–30% of a vCPU once they run out. A Kubernetes node runs many always-on controllers plus bursty work — Prometheus scrapes, SonarQube analysis, image builds — which drains credits reliably. The throttle then presents as unexplained slowness rather than an error, which is expensive to diagnose. m6i is fixed-performance: 2 vCPU means 2 vCPU, always.

Under Karpenter this softens into a preference rather than a lock — the NodePool permits a family set (m6i m7i m6a m5 c6i r6i) and Karpenter picks the cheapest instance that fits the pending pods.

Repositories

The repository Argo CD watches must never be the repository developers push application code to. If they are the same, CI triggers itself in a loop, every commit becomes a potential deploy, and you lose the audit distinction between built and deployed — the exact question asked during an incident.

Roughly a third of the application's .env is not secret. Moving it to a ConfigMap makes it diffable in pull requests and removes it from the blast radius. Treating an entire .env as one opaque secret is the most common secrets-management mistake.

Two manual gates, both deliberate. Argo CD's git credential cannot come from Vault, because Vault is installed by Argo CD — so it is created deliberately, documented in a runbook, and rotated once Vault is live. Vault cannot store its own recovery keys, so they go to AWS Secrets Manager and the root token is revoked.

Decisions

Thirteen records. Each carries the alternatives considered, the consequences accepted, and the trigger that should make us change our minds — because decisions without recorded reasoning become cargo cult within about six weeks.

ADR-001

Migrate Supabase → RDS PostgreSQL

Enables Vault dynamic credentials, which Supabase cannot provide. Verified as data-only.

ADR-002

All infrastructure in us-east-1

Cheapest, widest coverage. Latency mitigated at the Cloudflare edge.

ADR-003

One managed system node group; m6i over t3

Breaks Karpenter's chicken-and-egg. Fixed-performance avoids credit throttling.

ADR-004

Defer Linkerd, multi-AZ NAT, multi-AZ RDS

Each with a recorded cost and a revisit trigger. Consciously accepted, not overlooked.

ADR-005

Four repos; Jenkins CI-only, zero cluster credentials

Deployed state becomes a pure function of a git commit.

ADR-006

One cluster, two namespaces

A second cluster costs $73/mo plus nodes. Known weakness; mitigated by quotas and policy.

ADR-007

Vault OSS in-cluster, KMS auto-unseal

Auto-unseal is not optional — manual unsealing on every restart is the top cause of Vault outages.

ADR-008

External Secrets Operator over VSO

Manifests describe what secret is wanted, not where it lives. Changing store touches one resource.

ADR-009

IAM Identity Center replaces static keys

A leaked credential becomes a 60-minute problem instead of a permanent one.

ADR-010

RDS manage_master_user_password

The master password never enters Terraform state. Terraform cannot read it back — that is the point.

ADR-011

Cloudflare for DNS and edge

Free plan beats CloudFront for West African users, and hides the origin behind known IP ranges.

ADR-012

Adopt Karpenter

Bin-packs to the cheapest instance that fits and consolidates idle nodes. Replaces the Cluster Autoscaler and the Node Termination Handler.

ADR-013

Self-host SonarQube in-cluster

Heaviest single addition. Requires vm.max_map_count on the host or Elasticsearch crash-loops.

Phase plan

Eleven phases, each its own brainstorm → plan → spec → implement cycle, each producing a diagram update, an SOP, and a rehearsed rollback.

00Foundations & guardrailsRepos governed, secrets purged, Gitleaks active, SSO live, static keys deleted. $0 spent.
01Network & clusterVPC, EKS 1.31, add-ons, IRSA, access entries, Karpenter provisioning and consolidating.
02GitOps bootstrapStorage, metrics-server, Argo CD installed once by hand and thereafter self-managing. The cluster stops being something you talk to directly.
03SecretsVault with KMS auto-unseal, ESO, Reloader. Deployed by Argo CD; needs no ingress, so it comes first.
04Ingress & TLSCloudflare delegation, Traefik, cert-manager, external-dns — with the Cloudflare token read from Vault, not hand-created.
05Data layerRDS with managed master password, migration rehearsed and cut over, Redis, Vault database engine, restore drill timed.
06Continuous integrationJenkins on ephemeral agents, SonarQube, Gitleaks, Trivy gating. No cluster credentials anywhere.
07Application deliveryHelm charts, probes, HPA, PDB. Migrations move to a PreSync hook, out of container start.
08PolicyKyverno in audit before enforce, default-deny NetworkPolicies, quotas per namespace.
09ObservabilityPrometheus, Grafana, Alertmanager, Blackbox. Alerts tested by inducing real failures.
10Production readinessDR drill, SLOs, load test, cost review. Reliability gaps revisited with operational experience behind them.

Two orderings are deliberate and counter-intuitive. GitOps before Secrets: Argo CD lands right after the cluster so Vault itself is installed by Argo CD rather than adopted later — if Argo CD arrived after Vault, a Kubernetes Secret would get committed to git to make something work, and it would stay there. GitOps before CI: built first, Jenkins grows kubectl calls — exactly as the existing pipeline did.

Six pillars — the original five plus Sustainability, added in December 2021.
